## [Unreleased]

### 个人信息

- `/api/profile` 更新接口兼容历史或导入数据中的 `null` 清空值：富文本简介/经历描述、头像、主页、GitHub、项目/作品链接和作品图片会按空字符串保存，同时继续拒绝危险 URL 协议，避免个人信息页因旧数据返回 `400 VALIDATION_ERROR`。

### 求职申请跟踪 MVP

- 求职进展桌面端采用“优先处理 + 进展概览”双栏首屏，下方承接申请列表；窄屏自动转为单栏堆叠布局
- 移除阶段视图入口，保留进展概览阶段标签和全部申请状态筛选；列表新增按下一步、最近更新、投递日期和公司排序
- “记录一次进展”可在一次提交中联动阶段与下一步提醒，支持保持、指定日期、3 天后提醒或不再提醒；面试记录会建议同步到面试阶段
- 优先处理除逾期、今日、未来七天外新增“待规划”，让没有下一步日期的进行中申请仍有明确入口
- 优先处理固定展示最高优先级的 5 条，完整记录通过下方“全部申请”分页列表查看，不再提供“查看全部”和“收起”
- 申请详情抽屉改为“进展 / 简历 / 时间线”分区，Tab 在滚动时固定在顶部，已填写资料收纳到抽屉标题区且备注以更小字号直接换行展示；记录进展改为轻量子抽屉，取消会清空并收起，快捷模板以小字放在输入框下方，进展页最近动态默认 8 条且“查看全部”会切到时间线，时间线默认展示全部；简历 Tab 去掉小缩略图和重复的简历名称行，顶部用固定宽度控件选择简历和投递版本并在变更后保存/取消，选择历史版本时下方预览即时切换，只选简历未选版本时提示保存后生成当前快照，没有历史版本时显示可使用当前快照，只读快照按视口动态计算预览框高度并将滚动限制在预览框内；编辑以轻量叠层抽屉打开，关闭后保留原详情上下文，简历与版本选择在桌面端以固定宽度同行展示，备注输入降为轻量文本区
- 申请抽屉移除默认关闭叉，减少叠层编辑时的顶出距离；抽屉滚动不再带动底层页面，记录表单自动定位会避开固定 Tab
- 修复进展概览统计项的按钮背景溢出；阶段标签取消易重叠的装饰箭头，按可用空间均匀排列并在窄屏整项换行
- 优先处理按钮改为按真实分桶决策：待规划默认进入“指定日期”的安排下一步，到期/逾期事项默认要求重新选择下一步，面试阶段直接记录面试；统一提供“详情”次按钮，待跟进统计只滚动到优先处理区域不自动展开全部
- 求职进展 API 加固时刻与并发契约：所有时刻字段统一返回 UTC ISO 8601，事件 `occurred_at` 写入前归一化并按 UTC 排序；应用日历默认按 `Asia/Shanghai` 或 `APP_TIMEZONE` 计算 today、未来七天和顺延日期；联动阶段或下一步时 `expected_revision` 在校验层和服务层均必填
- 行动中心改为逾期、今日、未来七天、待规划分桶独立查询并返回 `total`/`has_more`/`limit`，不再用单个静默 `LIMIT 100` 导致逾期事项挤掉今日事项；时间线新增有界分页和事件类型判别 schema，禁止空跟进/空备注及非法面试 metadata
- 求职进展升级为最小过程工作台：默认行动中心（逾期、今日、未来七天）、阶段分组与全部申请管理视图；汇总可点击筛选
- 求职进展页面按当前项目视觉重新组织为“优先处理 + 进展概览 + 最近动态/全部申请”；新建、编辑和详情统一使用右侧 Ant Design 工作台抽屉
- 申请状态中文展示将 `screening` 从“筛选中”调整为更贴近求职者视角的“沟通中”，后端稳定枚举不变
- 申请详情工作台新增快捷记录模板、顺延 3 天、阶段推进和归档为未通过/已撤回操作
- 新增迁移 `008_job_application_events` 和受所有权保护的追加式活动 API；创建、状态变更、跟进、面试、备注和 Offer 可保留过程历史，状态变更与事件同事务
- 详情抽屉提供活动时间线、跟进/面试记录、下一步行动和真实 `StandardResumePreview` 投递快照
- 工作台进一步改为行动优先：逾期、今日和未来事项以可直接记录跟进/面试的卡片呈现；详情改用独立的跟进、面试、备注记录器，并在每次写入后刷新最新 revision，避免连续操作使用过期并发版本
- 简历/版本选择仅在表单打开后按需请求，简历支持服务端名称搜索；不再一次性拉取全部分页
- PostgreSQL DATE adapter 保留原始 `YYYY-MM-DD` 字符串，新增 Asia/Shanghai 日期不偏移回归
- 服务端汇总与行动中心按应用服务的本地 date-only 日历日比较，不再依赖数据库连接时区的 `CURRENT_DATE`

- 新增登录用户“求职进展”页面与 `job_applications` 迁移 006：可创建、编辑、删除、搜索、筛选申请并展示下次跟进时间
- 申请状态使用稳定英文枚举，前端统一映射中文；写入采用 `expected_revision` 乐观并发控制，过期更新返回 409
- 申请可关联实际投递简历版本；只选择简历时服务端事务内创建或复用 `source=application` 快照，所有简历和版本关系均联表校验所有权
- 不复制简历 JSON；简历或版本删除后申请保留但关联置空，用户删除级联清理；自动版本保留策略不清理 application 快照
- 首版不含提醒、拖拽看板、游客模式、MCP、后台或公开接口
- 修复 `/applications` 在认证状态水合前误跳登录；该路由现在等待服务端会话确认
- 新增服务端申请汇总、状态计数、快速改状态、逾期提示、职位链接和只读投递快照入口；列表及简历/版本选择加载失败会显示重试提示
- PostgreSQL 申请日期收敛为 `DATE`，迁移 007 按 UTC 转换历史时间戳；SQLite/PostgreSQL API 均返回稳定的 `YYYY-MM-DD` 或 null
- 未知申请存储错误仅记录服务端日志并返回通用 500，关联/不存在/revision 冲突分别保持 400/404/409

### 简历列表真实缩略图

- 正式用户列表继续使用不含正文的轻量分页 DTO；缩略图卡片接近视口后才按需读取对应详情，并以 React Query 缓存的真实 A4 预览替换结构摘要
- 请求失败或卡片尚未进入视口时保留结构摘要缩略图，避免列表因预览请求失败或慢网络而空白

## [1.0.3] - 2026-07-29

本版本集中完成项目评估中 P0 安全与数据一致性整改，并补齐可持续迁移、部署和回归验证基础。

### 简历版本历史 MVP（未发布）

- 新增受所有权保护的 `resume_versions` 快照、迁移 005 和 SQLite 实际迁移回归；SQLite 使用 TEXT、PostgreSQL 使用 JSONB，字段、约束与索引保持一致
- 新增版本元数据列表、单版本快照、手动创建和事务恢复 REST API；版本详情不会向非所有者泄露存在性
- 恢复严格校验 `expected_revision`，成功后递增当前简历 revision 并记录新的 `restore` 快照；失败回滚，不会产生半恢复状态
- 手动版本创建同样要求 `expected_revision`：编辑器先排空现有单飞保存队列并采用返回的最新 revision，保存冲突或失败不会产生旧快照；版本历史列表支持分页、错误重试和具名的查看/恢复控件
- SQLite 时间文本统一转换为 ISO 8601 UTC 后再交给浏览器；旧简历缺失或为空的模块配置会使用默认模块配置和顺序创建快照
- 编辑器新增可键盘操作的版本历史抽屉、只读预览和恢复二次确认；恢复后同步刷新编辑状态、预览、revision 与缓存
- 自动快照仅在成功保存后的后端合并路径生成，单简历至少间隔 10 分钟、最多保留 30 个 `auto` 版本；手动版本上限 100，`manual`/`restore`/`application` 不参与自动清理
- 游客模式、复杂 JSON/富文本差异比较和版本删除暂不支持；本期未新增 MCP 工具

### 安全

- 浏览器登录态迁移到 `HttpOnly + Secure（生产）+ SameSite=Lax` 会话 Cookie；登录、注册和 OAuth 回调不再向前端返回 JWT，新增服务端登出接口
- 新增 `auth_sessions` 服务端会话登记与迁移：仅保存 JWT SHA-256 摘要，登出、改密、改名和账号禁用可立即撤销旧凭证
- 生产环境强制校验 `JWT_SECRET`，拒绝缺失、少于 32 字符或已知弱默认值；临时预览签名同步收紧
- TOTP 密钥改为用户绑定的 AES-256-GCM 密文，生产环境新增独立且必须稳定保存的 `TOTP_ENCRYPTION_KEY`；历史明文由迁移 003 原位加密
- 启用 OTP 时生成 10 个一次性恢复码，服务端仅保存用户绑定的 HMAC 摘要；登录原子消费，支持重新生成和用于禁用 OTP
- 启用或禁用 OTP 会撤销该用户全部旧会话并为当前客户端轮换 Cookie；登录页与安全设置页补齐恢复码交互
- 修复公开简历 JSON-LD 的 `</script>` 存储型 XSS，新增专用安全序列化器和回归测试
- 公开简历 API 改为最小 DTO，不再暴露内部简历 ID
- 增加 CSP、HSTS、`nosniff`、Referrer Policy、Permissions Policy 和点击劫持防护响应头
- 登录、注册、OTP、OAuth、MCP Key 和 MCP 端点增加进程内限流与标准 `429` 响应
- 全部 19 个 JSON 写接口接入共享 Zod 运行时 schema；损坏 JSON、非对象请求、错误字段类型、非法 slug/role/revision 和超量批处理稳定返回 `400 VALIDATION_ERROR`
- 全部 18 个动态 API 路由和 8 组查询参数接入共享 Zod 校验；资源 ID 强制 UUID，筛选枚举、搜索长度、分页边界和重复单值参数不再被静默接受
- JSON 请求体改为 1 MiB 上限的流式读取，并限制嵌套深度、值节点数量和单字段长度；超限稳定返回 `413 PAYLOAD_TOO_LARGE`
- REST 与 MCP 共用细粒度富文本语义校验：限制 TipTap 节点层级、marks、样式属性、链接协议、16 层深度和 2,000 节点预算，字符串化的历史 `doc` 不能绕过校验
- 头像、主页、GitHub、项目及作品 URL 增加 2,048 字符和协议白名单，保留相对上传路径并拒绝 `javascript:`、`data:`、`vbscript:`、`ftp:` 等危险输入
- 通用错误 envelope 按 HTTP 语义统一为 `BAD_REQUEST`、`UNAUTHORIZED`、`FORBIDDEN`、`NOT_FOUND`、`CONFLICT` 和 `INTERNAL_ERROR`，保留 OTP、禁用账号等专用错误码
- 全部 API 响应增加 `X-Request-ID`，安全保留格式合法的入站追踪 ID，否则生成 UUID 并传递给 Route Handler
- GitHub 绑定回调重新校验当前服务端会话，并要求 state 中用户 ID 与会话用户一致，阻止伪造 OAuth Cookie 跨账号绑定
- 密码最小长度提升到 10 个字符

### MCP

- `read_only` Key 只注册读取工具，不能再调用修改、删除、发布等写工具
- MCP Key 鉴权关联当前用户状态；用户被禁用后旧 Key 立即失效
- 增加 scope 工具集契约测试和 MCP/IP 双维度限流
- MCP 入口按 schema、profile、resume 三个稳定领域拆分注册器；读写 Key 的 20 个工具名称改为精确契约测试，避免重构时漏注册

### 数据一致性

- SQLite 与 PostgreSQL 存储层新增事务接口
- SQLite 写事务增加进程内串行队列，避免同步 busy wait 阻塞首个 async 事务提交并错误返回 `SQLITE_BUSY`
- 注册用户、Profile 创建和一次性注册码领取改为单事务，注册码通过条件更新原子消费
- GitHub 首次注册与账号绑定写入改为事务
- 引入 `schema_migrations` 和顺序迁移；为注册码哈希建立唯一索引
- 新增迁移 004：安全归并 PostgreSQL 历史简历配置列到 `content` 并删除冗余列，使 SQLite/PostgreSQL Schema 恢复一致
- 简历新增递增 `revision`，条件更新冲突返回 `409`
- 编辑器自动保存改为单飞串行队列，只保留最新快照并展示保存失败状态
- Profile 缺失补建改为 `ON CONFLICT DO NOTHING` 幂等插入，消除并发首次访问的唯一约束竞态
- MCP 基本信息深度合并和数组条目操作改为 JSON 条件更新与有限重试，并发添加或修改不再静默覆盖；新增 4 项服务层并发契约测试

### 部署与工程

- 数据库初始化改为首次业务查询时显式等待，生产构建不再连接或修改数据库
- 公开 sitemap 改为动态生成，不再在构建期查询数据库
- Docker SQLite 数据目录固定为 `/data/careertrack.db`，使用可持久化卷并修复非 root 权限
- 新增 `/api/health` 数据库健康检查和容器 `HEALTHCHECK`
- 收紧 standalone 文件追踪范围，减少测试和文档进入运行产物
- 修复现有 ESLint 错误和警告，更新 E2E 会话、注册、公开页及安全用例
- 简历名称在创建和更新 API 统一执行 50 字符服务端边界校验，非法输入返回 `400`
- 补齐简历卡片和富文本工具栏的可访问名称、键盘编辑入口
- Playwright 默认使用隔离 SQLite 测试库和专用测试密钥，避免本机环境变量与安全限流污染回归
- 安全冒烟脚本可自动启动并清理独立测试服务；会话撤销加入单元、E2E 与真实接口冒烟覆盖
- 新增 `test:security-smoke`，覆盖 HttpOnly 会话、TOTP 恢复码、并发注册码、revision 冲突、公开 DTO、JSON-LD XSS、MCP 禁用用户和服务端会话撤销
- 新增 TOTP 密文用户绑定、恢复码摘要、并发单次消费和浏览器登录切换专项回归
- 新增 GitHub Actions CI：并行执行 lint/unit/build、PostgreSQL 15 集成和 Chromium 全量回归，浏览器失败产物保留 7 天
- 新增安全隔离的 `test:postgres`：随机子数据库覆盖自动建库、顺序迁移、注册码事务、JSONB/revision、TOTP 恢复码及历史列归并，结束后只删除生成的数据库
- PostgreSQL 正常启动路径不再创建探测连接池；仅在收到标准 `3D000` 缺库错误时使用短连接建库，并显式拒绝缺失 `DATABASE_URL`
- 公开简历客户端收敛为数据加载边界，将 A4 测量、分页、滑动和响应式缩放提取为独立组件
- SQLite/PostgreSQL 双形态 JSON 容错解析统一到 `parseJsonValue`，删除公开页、SEO 和 OG 路径的三份重复实现并补回归测试
- 编辑器、公开页、缩略图、模板和打印共用一套 A4 像素尺寸常量，避免分页阈值与渲染尺寸漂移
- 证件照工具将等比完整放入方形画布、白底绘制和 PNG/JPEG 编码收敛为共享 Canvas util，删除页面内两份重复实现
- 修复证件照工具切换导出格式时旧 React 闭包仍按上一格式编码的问题，并阻止快速连续切换产生的过期图片解码覆盖最新预览
- OTP 端到端测试避开验证码不足 2 秒即过期的时间窗，消除请求跨越 30 秒边界导致的偶发 CI 失败，不放宽服务端校验
- 基本信息表单按稳定职责提取配置驱动的额外字段组件，字段显隐、图标切换、Profile 按需导入和生日年龄计算收敛到独立组件与纯 util
- 修复隐藏额外字段时丢失 `avatar_left` 配置的问题；额外字段添加、图标和移除入口补齐键盘操作与可访问名称
- OTP 设置按敏感信息生命周期提取二维码 enrollment 与一次性恢复码组件；密码凭据和首次验证码不再共用 Form store
- OTP 启用和恢复码重新生成支持 Enter 提交，mutation 期间禁用重复操作；二维码生成失败会明确提示使用本地手动密钥，不再无限等待
- 清理 OTP 设置中的 Ant Design v6 弃用属性，并新增真实设置页启用、恢复码确认和重新生成浏览器回归
- 登录与游客编辑器保留各自 revision/API 和 localStorage 数据语义，仅将一致的旧数据初始化与模板/预览偏好操作收敛为共享 util/hook
- 编辑器 A4 预览按自身缩放状态和分页测量生命周期提取为独立面板，Shell 继续负责工具栏、模块和表单编排
- 预览字号、行距边界和默认值改为编辑器、REST 与 MCP 共享配置；REST 拒绝异常值，连续行距可在编辑器中准确显示和保存
- 预览字号/行距控件和缩放按钮补齐可访问名称，并新增配置保存、重载及局部缩放浏览器回归
- 编辑器数据 Hook 不再订阅完整 Zustand store；自动保存执行时读取最新快照，保持 revision/API 与 localStorage 语义不变
- 工具栏、模块侧栏、表单和 A4 预览建立独立 `useShallow` selector 边界，Shell 仅订阅预览显隐，普通正文输入不再重渲染页面入口和侧栏
- 新增 selector 契约测试，证明正文、保存状态和自定义标题只改变对应消费区域；侧栏折叠入口同步改为具名键盘按钮
- 删除没有调用方且不存在后端路由的头像上传 service/hook，头像流程继续使用 Gravatar 和本地证件照下载工具
- 主导航、用户菜单、模板卡、模块开关/拖拽、预览操作和富文本工具栏补齐语义按钮、可访问名称与键盘入口
- 新增主导航与编辑器关键交互可访问性 E2E 基线；完整 Axe/WCAG 审计仍保留为后续独立工作
- 富文本工具栏将自带状态的字号、行高、颜色、链接和对齐控件提取为稳定控件模块，主文件保留命令编排和布局
- 最终验收通过 ESLint、生产构建、28 个文件共 204 项单元测试、8 项安全冒烟及 Chromium 116/116 全量 E2E

### 性能与规模

- 个人简历、后台用户、后台简历、指定用户简历及注册码列表增加有上限的服务端分页；数组响应体保持兼容，分页元数据通过 `X-Page`、`X-Page-Size`、`X-Total-Count` 和 `X-Total-Pages` 返回
- 个人简历列表改为轻量摘要 DTO，不再查询或传输完整 `content`；卡片使用模板化结构缩略图，正文仅在进入编辑或打印时按需读取
- 后台表格改为服务端分页，搜索、筛选和每页条数变化会重置页码与当前页选择
- MCP `resume_list` 与 REST 共用查询上限，最多返回最近更新的 100 份简历
- 为用户创建时间、简历更新时间及注册码创建时间补充稳定分页索引，排序追加 `id` 防止同时间记录跨页抖动
- 新增 `test:performance` 编辑器防退化门禁和性能预算文档，覆盖预热页面加载、脚本解码体积及输入到预览可见延迟

### 已知限制

- 当前限流器为单进程内存实现；多实例生产部署必须在反向代理或 Redis 等共享存储层增加全局限流
- PostgreSQL 集成门禁需要 CI 服务或本地隔离实例完成真实执行；`TOTP_ENCRYPTION_KEY` 在线轮换和超大数据集所需的 cursor pagination 仍在后续路线中
- Redis 共享限流与审计日志已按当前产品阶段暂缓，不代表风险或需求已经关闭
