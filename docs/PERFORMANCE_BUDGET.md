# 性能预算

CareerTrack 当前使用端到端防退化预算，而不是在生产代码中加入临时计数器。
预算用于识别数量级退化；真实用户体验仍应结合生产 Web Vitals 观察。

## 编辑器基线

执行：

```bash
npm run test:performance
```

测试会创建隔离用户和空白简历，预热编辑器路由后刷新，并采集：

| 指标 | 预算 | 说明 |
| --- | ---: | --- |
| DOMContentLoaded | < 5000 ms | 预热后的编辑器页面 |
| Load | < 8000 ms | 浏览器 `load` 事件 |
| JavaScript decoded size | < 20 MiB | 开发测试服务加载的脚本资源上限 |
| 输入到预览可见 | < 1000 ms | 连续 5 次修改姓名后的最大延迟 |

Playwright 报告会附加 `performance-baseline.json`，包含本次实际值。阈值留有
开发服务器和 CI 机器波动余量，不应为了通过门禁而无依据放宽；若运行环境发生
变化，应同时记录新旧测量结果和调整原因。

2026-07-30 本地 Chromium/Next.js 开发服务首次记录：DOMContentLoaded
48 ms、Load 219 ms、44 个脚本资源合计约 12.0 MiB、输入到预览最大 48 ms、
平均 29 ms。该记录只用于后续同类环境对比，不代表公网真实用户指标。

## 后续生产观测

当存在稳定生产环境和监控接收端后，再接入真实用户的 LCP、INP、CLS。未明确
采集目的、保留期限和上报端点前，不在客户端静默发送性能或用户行为数据。
